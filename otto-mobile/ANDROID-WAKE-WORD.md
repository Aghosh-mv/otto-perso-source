# Android always-listening wake-word ("Hey Otto")

This documents the native Android work to make "hey Otto" work from the lock
screen / background on the Otto mobile app. The JS scaffold lives in
`wake-word.ts`; the pieces below are native and need an Android build
(`cd otto-mobile && npm install && cd android && ./gradlew assembleRelease`).

## Why native
The Web Speech API used on desktop doesn't run in React Native, and JS-side
`@react-native-voice/voice` recognition is killed by Android Doze when the app
is backgrounded / screen-off. True always-listening needs a **foreground
service** with a persistent notification + the `RECORD_AUDIO` permission.

## Two implementation paths

### A. Porcupine (Picovoice) — recommended
On-device wake-word engine. Free tier (no credit card), ~30 wake words
custom-assignable, very low battery/CPU.
1. Sign up at picovoice.ai → console → get a free `AccessKey`.
2. Train/download a "hey otto" wake-word model (`.ppn`) for Android.
3. Add the native module `picovoice-react-native` + the Porcupine Android binding.
4. Run Porcupine in a foreground service: `PorcupineManager` processes audio
   in the background, fires `onWakeWord` → your JS bridge activates the voice
   call (hand off to `@react-native-voice/voice` for the command, `/api/voice`
   for the reply, `react-native-tts` to speak it).
5. Put your Picovoice AccessKey in a BuildConfig / `react-native.config.js`.

### B. Voice-loop with foreground service (no Porcupine)
Use `@react-native-voice/voice` but host the recognition loop in a native
foreground service so Doze doesn't kill it. Heavier on battery, lower
accuracy, but no third-party key.

## Native pieces (either path)
- `AndroidManifest.xml`: add `<uses-permission android:name="android.permission.RECORD_AUDIO" />`
  and `<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />`
  (+ `FOREGROUND_SERVICE_MICROPHONE` on Android 14+).
- Write a `WakeWordService` (extends `Service`) that hosts Porcupine / the voice
  loop, calls `startForeground(...)` with a persistent notification
  ("Otto is listening for 'hey Otto'"). This is what keeps it alive screen-off.
- Request `RECORD_AUDIO` at runtime from the RN side on first launch.
- Bridge: expose `WakeWordModule` (ReactMethod `start()` / `stop()`) via
  `ReactContextBaseJavaModule` + register in `ReactPackage`.

## Constraints (matches the user's spec)
- Works when the phone is **powered on + online** (foreground service running).
- Dies in **airplane mode** (no network → can't reach `/api/voice`, though the
  wake-word itself is on-device with Porcupine — the brain reply needs net).
- Dies when **powered off** (no process).

## Google Play policy
Always-listening apps MUST disclose this in the Play Store listing
("Always-listening for 'hey Otto' — audio is processed on-device / sent to your
Otto server for the reply"). Add a prominent in-app consent screen before the
first `startForeground`. Provide a clear toggle to disable it.

## Wiring it in
In `App.tsx`:
```tsx
import { useEffect } from 'react';
import { startWakeWord } from './wake-word';
useEffect(() => {
  const stop = startWakeWord();
  return stop;
}, []);
```
